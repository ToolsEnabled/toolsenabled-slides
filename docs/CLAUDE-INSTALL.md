# Install ToolsEnabled Slides for Claude

**Linux tested; native Windows not yet supported.** Native Windows shutdown currently leaves a workspace lease that blocks subsequent sessions; Windows fixes and macOS qualification are pending. The instructions below apply to Linux. Works with Claude Code on Linux. No Claude Desktop bundle (`.mcpb`) is distributed with this release; `manifest.json` is an MCPB manifest kept for future Desktop qualification. ToolsEnabled is not affiliated with or endorsed by Anthropic. The 0.1.0 prerelease published the source and the Linux wheel bundle; 0.1.1 through 0.1.9 publish the source ZIP only and reuse that bundle. The repository is its own plugin marketplace for Claude Code and Codex (commands below). Native Desktop installation and trusted production signing require separate qualification.

## Prepare the runtime explicitly

Install Node.js 22+ and an existing CPython 3.12 interpreter. Claude Code starts the server with `node` from the PATH it runs with, so that `node` must be Node.js 22 or newer. For plugin setup, use the verified Linux x86_64 (glibc 2.28+) offline wheel bundle published with the 0.1.0 release; it is unchanged for 0.1.9 (the same six pins): [toolsenabled-slides-0.1.0-cp312-linux-x86_64-wheels.zip](https://github.com/ToolsEnabled/toolsenabled-slides/releases/download/v0.1.0/toolsenabled-slides-0.1.0-cp312-linux-x86_64-wheels.zip) (18297689 bytes, SHA-256 `a29454931420b8d9547eeb8d17c389a005cf0343a927d7a275f15eb3cab25fec`) with its [`.sha256` file](https://github.com/ToolsEnabled/toolsenabled-slides/releases/download/v0.1.0/toolsenabled-slides-0.1.0-cp312-linux-x86_64-wheels.zip.sha256). Only the Linux bundle was published. macOS and Windows profiles in the packaging metadata are unqualified candidates, not supported installations. Other Python/CPU combinations are not qualified by these offline bundles. The ordinary manual installation in README supports Python 3.10+ with its matching dependencies.

Download both files, verify the bundle with `sha256sum -c toolsenabled-slides-0.1.0-cp312-linux-x86_64-wheels.zip.sha256`, extract the ZIP outside the plugin directory (it unpacks to `cp312-linux-x86_64/`), and use that CPython 3.12 executable to run:

```sh
python3.12 /absolute/slides/tools/setup-runtime.py --runtime "/absolute/private/Slides Runtime" --wheels "/absolute/downloads/cp312-linux-x86_64" --pip-wheel "/absolute/downloads/cp312-linux-x86_64/pip-24.3.1-py3-none-any.whl"
```

Setup requires a new runtime directory with an existing parent. It verifies all six runtime wheel hashes and the supplied pip 24.3.1 installer hash against the shipped PyPI inventory, creates a venv, installs only those offline wheels with `--no-index --require-hashes --find-links`, checks imports and prints the venv Python path. The installer is unpacked into a temporary directory and removed after setup; it is not needed at runtime. Python distributions with working `ensurepip` may omit `--pip-wheel`. No runtime is bundled or copied from a developer machine. The source ZIP contains no wheels. Setup uses neither a package index nor a network installer; launching MCP never installs anything. Retain the external runtime's `slides-runtime.json` receipt. Run setup again into a new directory when a future release changes its lock.

## Claude Code

These commands were tested with Claude Code 2.1.296. The repository is its own marketplace (`.claude-plugin/marketplace.json`, marketplace name `toolsenabled-slides`):

```sh
claude plugin marketplace add ToolsEnabled/toolsenabled-slides
claude plugin install -s local toolsenabled-slides@toolsenabled-slides --config python_executable="/absolute/private/Slides Runtime/bin/python" --config node_executable=/absolute/node --config workspace_directory="/absolute/decks/Project Update" --config port=4599
```

The install then prints "2 userConfig options not yet set — run /plugin configure … or pass --config KEY=VALUE." This is expected: the two are the optional `renderer` (default `auto`) and `libreoffice_executable` (default empty, which finds LibreOffice on the PATH). Claude Code counts every option you have not saved a value for, even one with a default, and starts the server with the defaults; nothing else is needed.

Run installation from the presentation project directory with `-s local`. The GitHub marketplace tracks `main`; to install exactly the released bytes, verify and extract the release ZIP (README) and add that directory as the marketplace instead: `claude plugin marketplace add /absolute/slides`. Use a fresh extract for this, not the folder where you ran the README's source quick start: Claude Code copies the whole folder into its plugin cache, including a quick-start `.venv` (about 60 MB) that the plugin never uses. Update the marketplace (`claude plugin marketplace update toolsenabled-slides`) only after reviewing the new version. This stateful server can start when the plugin is loaded or when `claude mcp list` checks connectivity. Claude Code runs `node ${CLAUDE_PLUGIN_ROOT}/slides-mcp.js` with no other arguments and passes each setting to it as one environment variable, spaces included. `node_executable` is the Node.js that the `/slides` panes run: use an absolute Node executable, not a shell wrapper or npm command. Without the Python and workspace settings the plugin installs but Claude Code starts no server; without `node_executable` the server runs and the panes ask you to configure Node.js. The workspace must be outside the plugin cache. It holds deck files, assets and private `.slides-state`; keep the runtime outside both the plugin cache and workspace. Use a distinct workspace and local port for simultaneous clients.

Start `/toolsenabled-slides:toolsenabled-slides` and describe the deck or changes. The skill teaches read → lock → edit → readback → lint. Human pause, undo and protection controls remain in the dashboard. MCP export is available when requested; it writes only new workspace destinations.

Configured paths are saved in user options. For a project-specific local override, pass `claude --settings /absolute/project-options.json` with:

```json
{"pluginConfigs":{"toolsenabled-slides@toolsenabled-slides":{"options":{"python_executable":"/absolute/private/Slides Runtime/bin/python","node_executable":"/absolute/node","workspace_directory":"/absolute/decks/Project Update","port":4599}}}}
```

Keep machine-specific options out of shared source control. For Codex, add the same repository as a marketplace (`codex plugin marketplace add ToolsEnabled/toolsenabled-slides`; `.agents/plugins/marketplace.json` names it `toolsenabled-slides`), then install `toolsenabled-slides` from that marketplace in Codex's `/plugins` browser. The Codex manifest uses the relative Node entry `./slides-mcp.js` with `cwd: "./"`, which Codex resolves against the installed plugin. It does not use Claude variable substitution. Before launching Codex, configure `SLIDES_WORKSPACE` as an absolute workspace outside the plugin cache and `SUITE_PYTHON` as the absolute prepared venv Python; set `SUITE_PORT` for concurrent workspaces. The inline `env_vars` allowlist forwards those three settings plus optional renderer/LibreOffice, allowed-origin and timeout settings; Codex otherwise filters inherited variables. Plugin startup requires Node.js 22+, an absolute prepared external Python interpreter and a matching runtime receipt and dependency versions. Missing Python configuration never falls back to PATH or a plugin `.venv`. The workspace and runtime must not contain one another or overlap the plugin cache, including ancestor, sibling-cache and resolved alias paths. These checks precede state creation. Claude Code maps its configured workspace, Python, port, renderer and LibreOffice options into the launch environment and starts the same `slides-mcp.js` entry with `SLIDES_PLUGIN_MODE=1`, so these checks apply to it in the same way. The unpublished Desktop manifest maps the settings into the environment and literal argv of its Python launcher, which establishes the same settings before Node startup. Optional `renderer` defaults to `auto`; optional `libreoffice_executable` defaults to empty (normal PATH discovery), and any nonempty value must be an absolute path. Choose that option for LibreOffice installations outside PATH, such as a custom Linux installation. The plugin fixes extra allowed origins to none, HTTP header/body deadlines to 10/15 seconds, and MCP requests to their ordinary per-tool deadlines. Direct registration retains the advanced environment overrides documented in README. Use the print-only registration helper for direct registration without plugin loading. The historical `.mcp.codex.json` sample is no longer shipped.

## Find and recover the human dashboard link

Open the one-time link before giving the agent presentation work. The link is a bearer capability. Agents with file or shell tools can read the host log while it is unused; the dashboard boundary does not protect against another process with your OS identity.

In Claude Code 2.1.296, startup stderr is recorded under `~/.cache/claude-cli-nodejs/<cwd-slug>/mcp-logs-plugin-toolsenabled-slides-slides/<timestamp>.jsonl` (it can be labelled an error entry). The cache base may change with XDG settings. For a human-controlled log, start the client with `--debug-file /absolute/private/claude-debug.log`; `--debug` MCP diagnostics are also available. Search only your current project's plugin log for `/studio#launch=`; do not paste that URL into agent chat or a shared issue.

For Codex, use the persistent studio route so the human receives the link directly in their terminal. Before opening Codex, set the same absolute `SLIDES_WORKSPACE`, prepared `SUITE_PYTHON` and `SUITE_PORT` values that Codex will forward, then run `SLIDES_PLUGIN_MODE=1 node /absolute/slides/src/cli/studio.js`. Open the one-time link printed in that terminal and keep the authenticated tab. Start Codex afterward; its plugin attaches to the existing workspace and reports a clean studio URL. Closing the Codex session releases its locks and leaves this human-owned studio running. The tested route does not depend on a Codex stderr-log location. To recover the dashboard, stop and restart the terminal studio, open its new link, then reconnect Codex. Never ask the agent to find the launch link.

For a direct Node launch, the link is printed on the terminal's stderr. Native Claude Desktop installation and diagnostics are outside this Linux release's qualified scope.

If the ten-minute link expired or another client consumed it, use the host's human MCP controls to stop and reconnect the owning Slides server. For a persistent studio, stop and restart its terminal process. This invalidates the previous dashboard session and prints a new one-time link while preserving the workspace model. Attached clients must reconnect afterward. There is no unauthenticated HTTP or MCP command to issue dashboard credentials. Do not delete workspace state or leases as part of plugin installation or recovery.

## Claude Desktop and registry

No `.mcpb` is distributed with this release. `tools/package-mcpb.py` can build a source-only review artifact from `manifest.json` for future native Desktop qualification; it is not a supported installation route in this Linux release. Its configuration requires a prepared Python executable, Node executable, workspace and port. The proposed launcher runs the external Python executable, checks the lock and launches the existing Node stdio server. A bundled workflow skill does not establish automatic skill loading in Desktop. This local server does not run in claude.ai chat.

`tools/package-mcpb.py` uses the unmodified pinned mcpb 2.1.2 CLI with a fixed build clock and normalized modes. Two unsigned builds must match. `server.json` is an external, unpublished Registry draft generated from signed artifact bytes; it is excluded from source, ZIP, marketplace and `.mcpb`. After the reviewed source has been pushed and tagged and production-signed bytes uploaded, the release owner runs `tools/generate-release.py --source /absolute/checkout --repository https://github.com/ToolsEnabled/toolsenabled-slides --tag v0.1.9 --commit FULL_PUSHED_COMMIT --signed-mcpb /absolute/release.mcpb --release-url HTTPS_TAGGED_RELEASE_URL --output /absolute/new-sidecars --description "Create and edit local PowerPoint decks with a live studio, slide locks and portable exports."`. It verifies the remote peeled tag, pushed plugin identity and downloaded signed bytes before writing external `server.json`, `SOURCE-PINS.json` and `marketplace-entry.json`. The description is carried verbatim; it is never shortened. Signature trust and native qualification are separate gates. `registry-draft.py` remains for explicitly unpublished review examples. Production signing, namespace DNS verification, remote publication, directory submission and native Desktop installation are release-owner actions.

A development signature establishes no publisher trust. Stock mcpb 2.1.2 verification has a known failure even for signed bundles; preserve its result alongside independent OpenSSL CMS verification and a tamper negative control. No production signing or Desktop acceptance is implied by local schema validation.

## Privacy and support

Slides edits local files and serves a loopback dashboard. The MCP host receives tool results and may apply its own service/data policy. Slides has no built-in provider or credential store. See [SECURITY.md](../SECURITY.md), [ToolsEnabled privacy policy](https://toolsenabled.ai/privacy/) and contact [support@toolsenabled.ai](mailto:support@toolsenabled.ai).

## Startup environment contract

`SLIDES_WORKSPACE` and `SUITE_PYTHON` select the required external workspace and runtime. `SUITE_PORT` defaults to 4599. `SLIDES_RENDERER` defaults to auto and `SLIDES_SOFFICE` to PATH discovery; both are optional. The optional direct-registration settings `SUITE_ALLOWED_ORIGINS`, `SUITE_HEADERS_TIMEOUT_MS`, `SUITE_REQUEST_BODY_TIMEOUT_MS` and `SUITE_MCP_HTTP_TIMEOUT_MS` retain the documented defaults above when absent; Codex explicitly forwards them when supplied. Claude hosts explicitly assign their standard defaults. The Linux OS supplies PATH. Session identity, editor identity, loopback host, the ownership pipe flag and platform executable-search protection are derived inside Slides and must not be copied from host configuration.

## User commands

Claude Code provides the read-only `/slides` panes (tested with 2.1.296); the bare command opens `home`. They use the configured Node runtime and external workspace without MCP calls, model turns, editor registration, server startup or permission prompts. Use `1` to `8` for details, `n`/`p` to page, `b` to return, `r` to reload, `h` for home, `k` for help, and Esc or `q` to close. Help shows two commands per page with their descriptions and Codex equivalents. Other views show eight records per page. A changed snapshot requires an explicit reload. Detail text is bounded and marks truncation. Status offers a renderer probe only when you press `v`; opening the pane never runs it.

Native action commands start ordinary model work with the usual tool permissions. Type the full `/toolsenabled-slides:slides-…` name: unprefixed action names did not resolve when last checked (2.1.287). Panes never put workspace content into model context. Codex has no plugin slash-command registration; its equivalents below are CLI views and the `$toolsenabled-slides:toolsenabled-slides` skill. A Codex command typed after an exclamation mark runs in a shell, and its output enters the next model turn, so the CLI quotes workspace data and applies the same secret/control filters. This mapping is not native slash-command parity.

In CLI examples, replace `<plugin>` with the absolute installed plugin directory (the parent of `src/`: a version folder under `~/.codex/plugins/cache/toolsenabled-slides/toolsenabled-slides/`), `<ws>` with the configured workspace, and `<port>` with its port. Node and workspace settings are literal arguments. `ppt` is not automatically placed on PATH by plugin installation. Optional selectors in brackets are notation, not literal arguments. For object history, pass three words: `history s1 element e1` or `history s1 decor d1`.
